# GPT-6.2 Sol 向けの開発指示の調整

## 要求と設計

AGENTS.md とリポジトリ内のスキルを対象に、YAGNI、KISS、t-wada のテスト駆動開発、決定論的な検査の優先を手順へ反映する。変更の種類から読む資料と検査を選べること、未達の条件を識別できることを受け入れ条件とした。

現行のスキルは `develop-process` の1件。`develop-worker-process` は存在しないため、共通手順と3つの参照を使う構成とした。AGENTS.md の固定制約を維持し、スキル本文に調査・設計、Red、Green、Refactor、最終確認、完了条件を置いた。UI・BLE と依存・アプリのセキュリティは該当する参照に置いた。スキル検証には既存の検査器を使い、モデルで確かめる対象を適用条件、実行順、完了判断の変更に絞った。Lean 4 固有の記述は共通手順から外した。

## 調査根拠

2026-11-24 に確認した。

- テストリストから一件ずつ、意図した失敗を確認して必要な実装と整理を進める手順にした。[t-wada「テスト駆動開発の定義」](https://t-wada.hatenablog.jp/entry/canon-tdd-by-kent-beck)
- 依頼の到達点、既存コードを再利用する条件、実測で判定できる検査とレビューの使い方を確認した。[Using GPT-6.2](https://developers.openai.com/api/docs/guides/latest-model) 、[Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)
- 依存診断と署名・provenance の検証コマンドを確認した。[npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/)

## レビューと検証

設計と最終差分をレビューし、機能修正、依存更新、文書修正、開発対象外の依頼での適用条件を読み合わせた。変更対象は AGENTS.md、`develop-process/SKILL.md`、参照文書3件。変更前後を比較し、固定制約、既存スクリプト、アプリのソース・テスト、仕様、依存ファイルが一致することを確認した。

| 検査                                                    | 終了コード | 結果                                                                  |
| ------------------------------------------------------- | ---------- | --------------------------------------------------------------------- |
| `npm run skills:check`                                  | 0          | 1スキル、参照15件、エラー0件                                          |
| `npm run skills:test`                                   | 0          | 23件合格                                                              |
| `npm run format -- --check` に変更した指示文書5件を指定 | 0          | 全件合格                                                              |
| `quick_validate.py`                                     | 1          | `ModuleNotFoundError: No module named 'yaml'`                         |
| Ruby/Psych による YAML 構文・必須フィールドの検査       | 0          | 合格                                                                  |
| Codex App Server の `skills/list`、`forceReload: true`  | 0          | `develop-process` をリポジトリの有効なスキルとして読み込み、エラー0件 |

通常のサンドボックスで拒否されたスキル文書への書き込みと App Server のローカル起動は、対象ファイルへの反映と読み込み確認に限る許可を得て実行した。差分照合には一時ディレクトリのコピーを使った。アプリのコードと依存が一致しているため、アプリの単体・E2E・SSG 検査、依存の脆弱性診断は適用外とした。

## 未確認の項目

別セッションで GPT-6.2 Sol に依頼を実行させる評価は、隔離コピーのソースがモデルサービスへ送信され得ることを理由に自動承認レビューで拒否され、起動前に停止した。上記の結果は構造、内容、読み込みの確認を対象とする。

## ローカルコミット

ユーザーの「変更内容コミット」により、この変更の差分確認、ステージング、ローカルコミット、結果確認に Git 操作の例外が許可された。指示文書と本ログに加え、検証結果を再現するため、AGENTS.md の参照を検査する既存差分とその回帰テストをコミット対象とする。

コミット前に `npm run skills:check` と `npm run skills:test` を再実行し、参照15件とテスト23件の合格を確認した。検査スクリプト2件を対象にした `npm run lint --` と、コミット対象8件の書式検査は終了コード0。
