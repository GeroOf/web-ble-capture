# セキュリティレビュー

変更に関わる項目を確認し、依存とアプリの結果を個別に記録する。指示文書では、記載する操作が `@AGENTS.md` の作業権限・通信・保存の制約に沿うか確認する。

## パッケージ

- `@package.json`、`@package-lock.json`、インストール済みの版を照合する。開発・ビルド用と推移依存も含める。
- `npm audit --include=dev --audit-level=low --json` と上流の公式情報を確認し、指摘ごとに依存経路、影響条件、修正版を特定する。通信エラーは診断未完了として記録する。
- 変更する依存の配布元、保守状況と管理者の変更、インストール時処理、lockfile の取得 URL と integrity を確認する。署名と provenance は `npm audit signatures` で確認し、欠落、未提供、検証失敗を区別する。
- 指摘の原因を解消できる互換の安定版を npm で採用する。インストール時スクリプトは原則抑止し、必要なものは内容を確認してから実行する。更新後は版を照合し、再診断と `@docs/spec.md` の依存更新後の検査を行う。

## アプリ

- デバイス名、UUID、パケット、設定値の形式・長さ・件数を入力境界で検証し、負荷と状態の上限を確認する。
- 外部データはテキストとして表示する。HTML・コードとして実行される経路、外部送信、永続化、ログ内の機器識別情報を確認する。
- BLE の対応判定、権限、解放は `@AGENTS.md` と `@.agents/skills/develop-process/references/frontend-best-practice.md` に沿って確認する。
- CSP は生成した HTML と配信設定で確認し、確認できた範囲を記録する。原因を修正したら、受け入れ条件に対応する回帰テストを実行する。
