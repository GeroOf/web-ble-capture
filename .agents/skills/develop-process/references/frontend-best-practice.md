# フロントエンドの設計・レビュー基準

UI・BLE の設計レビューとソースレビューで使う。共通工程は `@.agents/skills/develop-process/SKILL.md`、セキュリティの詳細は `@.agents/skills/develop-process/references/security.md` を開く。

| 対象                       | 確認すること                                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 静的生成とクライアント処理 | ブラウザ API の参照でビルドを失敗させない。静的 HTML の情報と操作案内を確認し、必要な部分だけを Preact で有効にする。                       |
| 型と境界                   | Props、状態、Web Bluetooth の値に型を付ける。外部入力は TypeScript の型だけで信用せず、実行時の形式・長さを検証する。                       |
| BLE の状態遷移             | 選択のキャンセル、権限拒否、接続失敗、切断、通知終了から復帰できる。通知の購読とイベント登録を解除し、重複受信を防ぐ。                      |
| 応答とメモリ               | 大量の通知でログや状態を無制限に増やさない。描画の負荷、操作の応答、配信 JS の増分を必要に応じて測定する。                                  |
| 操作と表示                 | キーボード操作、ラベル、モーダルのフォーカス移動・復帰、状態通知を確認する。Tailwind の既存の色・余白を使い、対応する全ロケールを確認する。 |

## テストの選択

- ユニットテストは Vitest で、データ変換の境界、非同期処理の失敗、購読解除など、変更した振る舞いを検証する。
- E2E は実ブラウザで主要操作の結果を検証する。BLE の模擬 API、固定データ、制御した時計を使い、実機や通信状況に依存する失敗を分離する。
- 非対応ブラウザ、JavaScript 無効、接続のキャンセル・切断など、変更に関係する利用条件も検証する。模擬 API では実機の互換性を証明できない。
