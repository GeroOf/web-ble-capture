# フロントエンド開発のベストプラクティス 2026

本プロジェクト（Web BLE Capture）における、2026年のトレンドおよびアーキテクチャ方針に基づいたフロントエンド開発のベストプラクティスを定義する。

## 1. TypeScript と型安全性の徹底

- **Strict モード前提**: `tsconfig.json` で strict モードを有効化し、暗黙の `any` を許容しない。
- **堅牢な DOM / Web API 型定義**: Web Bluetooth API など、DOM 拡張インターフェースに対する厳格な型推論とバリデーションを確保する。
- **フルスタックコンポーネント型化**: Preact コンポーネントの Props や State は、常に型安全性を維持して定義する。

## 2. アーキテクチャとレンダリング戦略 (Astro / SSG)

- **Astro Islands の活用**: 基本となる HTML を完全静的（SSG）で配信し、インタラクティビティが必要な部分（Web Bluetooth を利用するキャプチャ領域など）のみを Preact でコンポーネント化してハイドレーションする。
- **クライアントサイド処理の分離**: バックエンドを持たない本プロジェクトでは、すべてのビジネスロジックと外部機器通信を分離・カプセル化し、UI と密結合させない。
- **バンドルサイズの最小化**: 無駄な依存関係を取り込まず、不要な JS をロードさせないツリーシェイキングを意識する。複雑な状態管理ライブラリは避け、軽量なステート管理を原則とする。

## 3. パフォーマンスと Core Web Vitals

- **INP (Interaction to Next Paint) と LCP の最適化**: ユーザー操作から UI のレスポンスまでの遅延を最小に保つ。不要な再レンダリングを防ぐ構成を徹底する。
- **リソースの効率的な読み込み**: Web Bluetooth に関連する重い処理は、必要になったタイミングでのみ評価されるよう遅延ロード等の工夫を検討する。

## 4. スタイリング (Tailwind CSS ユーティリティファースト)

- **Tailwind への集約**: 新たにカスタム CSS ファイルをやたらと追加せず、極力 Tailwind CSS のユーティリティクラスを用いて設計・実装を集約する。
- **予測可能な UI**: デザインシステムとしてトークン（色、スペース、タイポグラフィ）に一貫性を持たせ、堅牢でクリーンなスタイルを構築する。

## 5. テストと静的解析 (Vitest / oxc)

- **Vitest による高速なテスト**: ユニットテストやコンポーネントテストに Vitest を活用し、各機能（特にパケット解析など純粋関数としてテスト可能な部分）の堅牢性を保つ。
- **oxc の活用**: 強力かつ高速な静的解析ツールである `oxc` を使い、Linter と Formatter による品質維持を開発ワークフローに統合し、レビュー前に常にクリーンな状態を保証する。

## 6. Progressive Enhancement とアクセシビリティ (a11y)

- **Graceful Degradation**: 実行環境（Safari 等）が Web Bluetooth 非対応の場合に画面がクラッシュしないよう、安全なガード処理とフォールバック UI を確実に実装する。
- **アクセシビリティの組み込み**: 開発初期からセマンティックな HTML を記述し、キーボード操作のサポートと適切な ARIA 属性を付与する。a11y は追加要素ではなく標準要件として扱う。
