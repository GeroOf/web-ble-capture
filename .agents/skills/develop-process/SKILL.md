# 開発手順

`@AGENTS.md` を読み、依頼された到達点まで進める。調査・設計だけの依頼は、その成果をレビューして報告する。確認待ちの項目があれば、影響しない作業を先に進める。

1. **調査と設計**。関連する実装・仕様・テストを読み、受け入れ条件ごとに確認方法を決める。既存の利用経路、境界・失敗時の挙動、固定制約への影響をレビューし、指摘を解消する。API や依存を選択・変更するときは、公式資料で仕様・互換性を確認し、根拠と確認日を記録する。
2. **変更**。振る舞いを変える場合は下記のテスト駆動開発を使う。アプリの仕様を変えた場合は `@docs/spec.md` に反映する。
3. **最終確認**。変更ファイルを整形し、最終状態で必須検査を実行する。変更箇所を読み直し、受け入れ条件、回帰、セキュリティへの影響を確認する。指摘を修正したら、該当する検査とレビューをやり直す。

## 振る舞いを変えるとき

入力・操作と外から観測できる期待結果をテストリストに挙げ、一件ずつ進める。

1. **Red**。選んだ項目を実行できるテストにし、実装を変える前に意図した理由で失敗することを確かめる。
2. **Green**。必要最小限の実装で同じテストと関連する既存テストを通す。
3. **Refactor**。必要な整理を行い、同じ検査を再実行する。

作業中に見つけた条件をリストに加え、対象の項目が済むまで繰り返す。Red の原因と Green の結果を記録する。

## 変更に応じて読む資料

- 画面表示・操作、BLE の設計と検証は `@.agents/skills/develop-process/references/frontend-best-practice.md`。
- 依存更新、セキュリティの調査・修正、通信・保存・権限に影響する変更は `@.agents/skills/develop-process/references/security.md`。
- AGENTS.md、スキル、検査スクリプトの変更は `@.agents/skills/develop-process/references/skill-validation.md`。

## 検査と記録

`@package.json` から変更に対応する既存コマンドを選ぶ。

- 書式は変更ファイルを指定し、`npm run format --` で整形し、`npm run format -- --check` で確認する。
- ソース、型、ロジックは影響に応じて `npm run lint`、`npm run check`、`npm test -- --run` で確認する。
- ブラウザでの表示や操作に影響する変更は `npm run test:e2e`。SSG を確認するビルドは、新しい一時ディレクトリを `npm run build -- --outDir` に渡す。
- 文書だけの変更は、影響する参照とコマンドの実行例を確認する。

受け入れ条件と必須検査を満たし、レビューの指摘を解消したら完了とする。未達の条件がある場合は、確認できた範囲と残る条件・理由を報告する。

`docs/agent-logs/YYYY-MM-DD_HH-MM-SS_作業内容.md` に、要求、調査根拠、設計とレビュー、変更、実行コマンド・終了コード・結果、適用外・未実行の検査と理由を残す。
