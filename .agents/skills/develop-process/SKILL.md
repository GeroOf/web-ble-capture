# Development Process Skill

## Context (適用コンテキスト)

Web BLE Capture プロジェクトにおける、設計決定、新機能の実装、既存機能の修正など、開発ワークフロー全体に適用する。コーディングエージェント（AI 含む）はこのスキルに定義されたプロセスとレビュー基準を厳密に遵守してタスクを遂行すること。

## Workflow (開発ワークフロー)

### 1. 初期構築プロセス

- プロジェクト初期化時に必ず以下を作成すること。
  - `docs/`
  - `docs/agent-logs/`

### 2. 設計・プランニング

- **保存先**: `docs/spec.md`
- **内容**:
  - アプリ概要
  - BLE キャプチャの対象・範囲
  - 画面構成
  - データフロー（※バックエンドなし前提）
- 実装を開始する前に、必ず設計ドキュメントを参照・更新すること。

### 3. 開発・実装プロセス

実装時は以下の順序を守ること。

1. **設計ドキュメント更新**: `docs/spec.md` を最新状態に保つ。
2. **実装**: 制約に従ってコードを記述する。
3. **Lint チェック**: `oxc` による lint チェックを実行する。
4. **フォーマット**: `oxc` による format を実行する。
5. **テスト実行**: `Vitest` によるテストスクリプトを実行し、テストを通す。
6. **作業ログ作成**: 下記のルールに従ってログを保存する。

### 4. 作業ログ（Agent Logs）作成

- **保存先**: `docs/agent-logs/`
- **命名規則**: `YYYY-MM-DD_HH-MM-SS_作業内容表題.md`
- **内容**:
  - 実施内容
  - 変更ファイル一覧
  - 技術的判断ポイント
  - 残課題（あれば）

## Review Criteria (レビュー基準)

実装後のレビュー時は、以下のすべての基準を満たしているか確認すること。

### 1. フロントエンド開発のベストプラクティス 2026 準拠

以下の参照ファイルを確認し、最新のベストプラクティスに準拠した実装になっているか検証すること。

- **参照先**: `.agent/skills/develop-process/references/frontend-best-practice.md`
- **重視ポイント**: TypeScript Strict, Core Web Vitals (INP/LCP) 対応, Tailwind CSS ユーティリティファースト, Vitest のテスト容易性, Progressive Enhancement 実践
- ※ RSC / サーバー依存設計は本プロジェクトでは採用しない。

### 2. セキュリティ

- XSS を誘発する実装を行わない
- `innerHTML` の使用禁止
- CSP を破壊する設計を行わない
- BLE デバイス情報を外部に送信しない
- ログに個体識別可能な情報を残さない

## Agent Behaviors (エージェント行動原則)

コーディングエージェントは以下の原則を常に心に留めること。

- **推測で実装しない**
- **設計判断は必ず文書化し残す**
- **最小変更・最小依存に留める**
- **「動く」より「壊れない」を優先する**
- 人間が後から読んで理解できるコードを書くこと

> **例外記録の原則**
> このスキル定義やすべてのルールに反する判断を行う場合、**必ず作業ログへ明示的に例外として記録すること。**
